# Emerald new-game SID RNG filter

The optional [Dewford phrase extension](DEWFORD_SID.md) additionally tests each SID-generating state against original phrase membership and recorded first-submission answers. It preserves advance witnesses and intersects actual candidate sets through this same pipeline, including wild PID/IV searches. Its timing model is conditional; it is not a claim that a working clock or a modified ROM always follows the calibrated initialization gap.

The optional filter is shared by SID Finder and Data Recovery. It uses the **original trainer TID**. Default scope is calls 1–3,600, inclusive, presented as approximately 0–60 seconds. Call ranges are hypotheses; seconds are not measured RNG counts.

## Verified source sequence

Checked against pret/pokeemerald commit `731ad5bfd6e6f265508d0efcca0ba42f9dcf5881`:

1. [`MainState_Exit`, naming_screen.c](https://github.com/pret/pokeemerald/blob/731ad5bfd6e6f265508d0efcca0ba42f9dcf5881/src/naming_screen.c#L696) calls `SeedRngAndSetTrainerId` when the player naming screen finishes fading out. Nicknaming a Pokémon does not take this branch. Use the final exit if naming is repeated.
2. [`SeedRngAndSetTrainerId`, main.c](https://github.com/pret/pokeemerald/blob/731ad5bfd6e6f265508d0efcca0ba42f9dcf5881/src/main.c#L208) reads the 16-bit hardware timer, seeds with that value, stops the timer, and retains that same value as the public TID. Using the final TID reconstructs its timer seed.
3. [`Random`/`SeedRng`, random.c](https://github.com/pret/pokeemerald/blob/731ad5bfd6e6f265508d0efcca0ba42f9dcf5881/src/random.c) zero-extend the seed, update the 32-bit state and return its upper half. [`random.h`](https://github.com/pret/pokeemerald/blob/731ad5bfd6e6f265508d0efcca0ba42f9dcf5881/include/random.h) defines multiplier 0x41C64E6D and addend 0x6073.
4. Post-naming speech in [`main_menu.c`](https://github.com/pret/pokeemerald/blob/731ad5bfd6e6f265508d0efcca0ba42f9dcf5881/src/main_menu.c#L1762) reaches [`CB2_NewGame`, overworld.c](https://github.com/pret/pokeemerald/blob/731ad5bfd6e6f265508d0efcca0ba42f9dcf5881/src/overworld.c#L1532), then `NewGameInitData`.
5. [`InitPlayerTrainerId`, new_game.c](https://github.com/pret/pokeemerald/blob/731ad5bfd6e6f265508d0efcca0ba42f9dcf5881/src/new_game.c#L84) combines `Random() << 16` with the retained public TID. That Random output becomes SID, before later map/truck setup.

No main-RNG reseed occurs in the inspected ordinary post-naming speech → trainer-ID path. The RTC seed in `main.c` is guarded by `BUGFIX` in stock Emerald and precedes the naming-screen seed anyway. Random2 uses separate state. These assumptions do not cover modified ROM routines.

[`VBlankIntr`, main.c](https://github.com/pret/pokeemerald/blob/731ad5bfd6e6f265508d0efcca0ba42f9dcf5881/src/main.c#L343) calls the same RNG during ordinary frames. Extra calls and transitions change the call count; visible control is later than SID creation. Subsequent calls cannot alter the stored SID. Enumerating every call in a generous window preserves compatibility regardless of which intervening routine consumed it. Fixed NPC trade IDs and IDs generated by other games are outside this model.

## Exact evidence intersection

`core/sidRng.ts` jumps to minimum−1, advances once for each tested call, and groups duplicate SID outputs while retaining all generating advances. Counts are never multiplied to estimate intersections.

Bounded PID pools use the joint solver's exact header, known plaintext, observed zero/nonzero nibble and partial checksum checks across every saved snapshot. Intersection retains actual joint hypotheses, including correlated wild PID/IV spreads. Wild H1/H2/H4 searches apply the SID window before the joint candidate safety limit. Disabling the filter reruns the unconstrained wild scope.

Unknown-PID digit models cover all 24 orders, nature residues and gender cases. Dynamic validation finds actual compatible PID witnesses across all snapshots and checksums. A witness proves that a SID is possible; it never becomes an entered or recovered PID. Broad PID pools remain broad. If a per-SID search bound prevents proof/rejection, that SID is retained and explicitly labeled **unresolved**, never silently excluded or claimed as a proven match. Unresolved summary-stat ranges outside wild generation remain separate from this stored-data model.

Result rows show SID, advances and Validate. Validation reports compatibility, not proof of trainer identity. Optional `sidRng` JSON/autosave metadata preserves scope without editing facts or observations. Zero survivors show Widen/Disable and explain that timing, facts or pixels may be incorrect. Unfinished experiments remain excluded.

## Reproducible Poochyena check

The review fixture corrects the Ruby/Emerald mismatch and leaves disputed pixels 122/130 unknown. No hidden PID/SID/IV facts are imported. TID 40492 generates **3,506 distinct SIDs** in calls 1–3,600; reference SID 37399 occurs at **advance 1,736**. Ending at 1,735 or starting at 1,737 excludes that genuine SID here. Timing alone leaves thousands of unknown-PID matches; combining bounded wild generation narrows actual correlated hypotheses further.

With the reference PID supplied only for validation, 4,394 curtain-compatible SIDs intersect to exactly **237**. With PID/IVs absent and the wild H1/H2/H4 seed-0 window 0–99,999, **144** joint hypotheses become **9** after applying the SID window. The genuine PID/SID/IV tuple survives. These are actual filtered sets, not count-based estimates or a guarantee of uniqueness.

Tests cover independent BigInt arithmetic, first-call/inclusive boundaries, duplicate outputs/all advances, actual set intersections, generated IV correlation, unknown-PID witness isolation, all 24 dynamic orders, conflicting snapshots, JSON reversibility and genuine-SID exclusion outside the window. No new emulator capture or measured new-game timing is claimed.
